# Experiment 431 — literal groups of 23

## Question

If a 621-label space were intended as 27 groups of 23, do literal consecutive 23-sticker groups expose a simpler or more stable symbol structure than the native 27-sticker grouping?

Use the 10 live canonical masters repeated through serial 621. Split 001..621 into exactly 27 consecutive blocks of 23. For each block record the slash/dash/dot census across the live completion family.

No reordering or optimization is allowed.

## Result

Only **13 of 27** 23-sticker blocks have a completion-invariant symbol census. The other 14 change as the unresolved live state changes.

Invariant blocks and censuses `(slash,dash,dot)`:

```
3  = (14, 9, 0)
6  = (10,13, 0)
7  = (12,11, 0)
8  = (13,10, 0)
11 = (11,12, 0)
14 = ( 7, 0,16)
15 = (12,11, 0)
16 = (14, 9, 0)
17 = (13,10, 0)
20 = (10,13, 0)
21 = (14, 9, 0)
22 = (12,11, 0)
25 = (11,12, 0)
```

There is no common census, one-exception rule, or obvious 23-block alphabet.

By contrast, splitting the same hypothetical 621 run into **23 blocks of 27** is completely aligned with the native carrier. The primary quarter censuses are fixed by the current model and the tail quarter is separately typed.

## Interpretation

This distinguishes the two arithmetic readings of `621=23×27`.

- **27 groups of 23:** arithmetically valid but cuts across H108 and produces no comparably clean block grammar.
- **23 groups of 27:** exactly follows the independently established quarter carrier.

So even after explicitly testing “lots of 23,” the evidence continues to prefer **23 as the number of 27-sticker groups**, not 23 as the group width.

## Disposition

Negative for 23-sticker chunks. Positive only for the already-established 27-cell grouping conditional on a 621 endpoint.
