# INSIDE CE search and image discovery: pre-deployment engineering audit

**Date:** 16 October 2026. **Mode:** VALIDATE existing execution/coverage facts, DISCOVER proposed retrieval and visual methods. **Scope:** search and image leads for new *public* numbered stickers, source references and acquisition statements, without contacting CE owners. This assessment cross-reads the current repository's search/infrastructure docs, acquisition/visual scripts and tests, plus the upstream canonical owner register. It is not a new completed Internet-wide search. **No new sticker or owner identified.**

## Decision

**Do not dispatch the 28,188 planned multilingual searches or a large image-ingestion job yet.** The immediate blocker is **unmeasured live source-level recall** on most platforms, not lack of generated search terms. An October 16 audit observed zero workflow-dispatch runs in GitHub Actions history even though most campaigns are manual-only. Successful offline planner/CI runs are not search executions; however one-shot PR live experiments did occur (Bluesky, Reddit source checks, eBay/CDX, image captures). Attribute measured findings to the exact run, not to a plan.

Current strengths to **reuse**, not replace: 50 native-language profiles; 491 forum targets and route inventories; original-source/archival controls; bounded provider-specific pipelines; 17-surface failure matrix; 12 gold targets (only **10 currently exact-scoreable original locators**); canonical source/owner reconciliation; original JPEG/PNG/WebP SHA256 provenance; a validated >82-photo sticker reference index; dHash/aHash full and overlap-window review matching; distinct official/product reference roles; optional zero-shot CLIP *ranking*, not ownership certification; fail-honest acquisition reports; no network traffic from ordinary CI. See [reliability audit](inside-ce-discovery-reliability-audit-2026-10-16.md), [gold audit](inside-ce-cold-recall-controls-audit-2026-10-16.md), [image index](inside-ce-image-provenance-and-gold-source-recall.md), [new corrected owner handoff](inside-ce-raezores-public-lead-handoff-2026-10-13.md).

## Concrete defects found in this review and patched

1. **Image budget starvation by lexicographic source ID.** `fetch_html_images.select()` grouped valid assets by `source_id`, then took up to `per_page` images from `sorted(grouped.items())` until the overall `total` was exhausted. When total is smaller than all eligible source images, pages with early IDs can crowd out other pages even if later pages contain stronger keyword evidence. **Patch:** within each source retain strongest independent asset variants; globally perform scored first-choice **round-robin by source**, then second choices, etc. No source exceeds `per_page`; `total` remains fixed. Existing waterfall `eligible_asset_families_not_selected_by_budget` remains an auditable censoring metric. Add no-network tests for later-ID retrieval, one-per-source coverage, fairness, and source caps.
2. **HTML media blind spots.** `discover_html_images.py` extracted `img`/`source`, OpenGraph/Twitter meta and lazy `srcset` but did not extract inline CSS backgrounds, JSON-LD `image`/`thumbnailUrl`/`contentUrl`, video `poster` or direct linked image `a[href]`; it also ignored document `base[href]`. **Patch:** parse these additional explicit image surfaces from **already acquired** public HTML. URL normalization still blocks non-HTTP(S) and data/blob/javascript; actual downloads still require allowlisted HTTPS media hosts and verified image magic/size. The JSON-LD parser is bounded and ignores malformed data. Tests cover positives, invalid JSON, and unsafe URI types. **Coverage is still not complete**: JavaScript-only dynamic resources, external CSS, image search index result thumbnails, video frames and archived media require separate stages.
3. **Canonical closure not an image-classifier output.** The already merged [16 October reconciliation PR #299](https://github.com/gamesbyian/GRA-EDISNI/pull/299) fixed the known /043 and lost L46 duplicate-owner handoff, including tests against current community master rather than trusting an old archived snapshot. Preserve this gate; do not let CLIP, image hashes, matched photograph URLs, duplicate retailer images, or an absent username *ever* increase verified sticker or owner counts automatically.

These patches make small deployments more reliable, but **they do not fix source search recall, permissibility, unexhausted pagination or photo-level sticker legibility**.

## Proposed evidence and search architecture

**Immutable source-first lineage:** `search_task` → `provider_request` → `result_page` → `original_post/page` → `media_urls` → `original_media_bytes` → `visual_matches` → `human review` → `canonical_case_resolution`. Every edge stores source locator, actual retrieval status, date/version, relevant response/hash and censoring. This is an event log, not just the latest winner. Separate earliest publication date, provider `indexedAt`, capture date, acquisition date, and claim date.

**Query and platform controls:** Freeze each provider's known-positive and negative-control queries without user handles, sticker numbers, known post URLs or source IDs in search expressions. Observe actual recall at original-post / original-image / original-comment level; evaluate `precision@20`, `recall@20`, source attempts, response validity, pagination/censoring, duplicates, original-byte success and cost per *novel vetted original source*. A retrieved thread title is not a retrieved comment; a media-preview URL is not a full image. Gold G05 (eBay shortener) and G10 (Instagram profile) remain unscoreable as **original-image targets** until exact source locators are recovered.

**Visual stage layering:** (1) original bytes, EXIF-transposed pixel hash and exact duplicate groups; (2) image variants and review-only dHash/aHash; (3) calibrated PDQ/pHash and rotated/cropped views; (4) source-local patch/sticker ROI retrieval or embeddings where needed; (5) optional CLIP/embedding *ranking* under reviewed label prompts; (6) manual sticker serial/symbol/background reading. Do not start with OCR on full cluttered photographs or treat model probabilities as confirmations. Validate the difficult cases: a sticker occupies <5% of a collector's photo, darkness/reflections/low-res, photos of game-only wrappers, and repeated official publisher photography.

**Fair source-level budget:** count media candidates *before* and *after* CDN allowlist, official promotional filename filter, per-source cap, global cap, fetch status and bytes, and the visual-index cap. First-pass source diversity gets priority, while source-native specific targeted searches may use their own bounded profile. E.g. 48 transferred assets with `per_page=8` should not all come from six alphabetical pages when one high-value photo from a later source could have been scanned.

**Review queue:** a static, self-contained HTML contact sheet with thumbnails and original public source links, source dates, match kind, known canonical case, acquisition state, photo legibility and explicit disposition (`not_playdead`, `official_reuse`, `known_case`, `new_source_needs_review`, `image_sticker_unreadable`, `physically_verified`). Preserve the full ranked alternatives rather than only a top-one CLIP label; sample unranked/low-score records for false negatives. Never place non-consensual personal information, account enrichment or owner-contact tasks in the automated workflow.

## Exact pre-deployment gates

| Gate | Pass condition | Outcome if failed |
|---|---|---|
| **G0. Source legitimacy** | Every planned retrieval has approved public URL/permission basis and host-specific reasonable limits; no credential evasion or reattempts on refused cursors. | Do not request; record blocked/unattempted. |
| **G1. Execution accounting** | Exact task count equals executed + refused/not-attempted; no silent zero-payload success. Timestamp, original URL, content hash and provider pagination state retained. | Fix before broad crawl. |
| **G2. Search recall** | At least **two** distinct dated known-positive original sources plus **one** ambiguous negative per target provider. Original-source retrieved, not merely index URL; report rates even if 0. | Restrict platform until diagnosed, do not add thousands of queries. |
| **G3. Visual fairness and coverage** | Synthetic round-robin/old-starvation fixture passes. URL/image byte and image-index waterfalls reconcile; known representative original photos are not systematically rejected by URL heuristics. | Fix caps/allowlist/selector first. |
| **G4. Visual retrieval quality** | Blindly recover same-image resized/recompressed positives, cropped/rotated and cluttered sticker-photo positives from a held-out source set. Report recall@20, false-positive marketing images and source diversity. | Keep as human-review aid only; test additional features. |
| **G5. Canonical owner closure** | Reconcile candidate public handles, listing IDs, known transferred copies and loss statuses against **current** twinysam sticker register and superseding local reports. No new-sticker count from image similarity. | No Raezores handoff. |
| **G6. Tiny authorized live pilot** | 12–24 request budget spread across providers with measured success and false negatives, 24–48 eligible source images max with per-page fairness, archived full response metadata, independent spot-check of discarded images. | Stop, analyze failure and revise source-specific method. |

### Staging

**Do now before next network deployment:** merge tested fairness/HTML carrier patches; regenerate original-source controls; validate canonical drift using live upstream; freeze source-ready manifests; test a *small* subset of real authorized web-index/YouTube/Reddit-native queries, not just offline planners.

**Next small live pilot (separately explicit):** 12–24 measured queries and up to 48 downloaded already-approved media assets, with 5–10 manually inspected high- and low-ranked images and original-source verification. Report *source-level retrieval success and coverage waterfall*; absence after 403/429 or untraversed pagination is censored.

**Only after actual recall data:** evaluate targeted Browsertrix and ArchiveBox/WARC fallback, PDQ vs current hashes, CLIP/FiftyOne or fastdup-based embedding ROI search. An opt-in heavyweight GPU/ML dependency is reasonable only if it improves held-out recall, not because the package exists.

**Next dispatch criterion:** measured original-source recovery and false-negative accounting are more valuable than another 28k speculative queries. A good run can return zero new stickers, as long as it honestly accounts for every attempted and unattempted source and reveals which search lane can produce useful novel original evidence.
