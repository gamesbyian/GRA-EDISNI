## Why revisit this now?

One proposed bridge extracts the **nine numerical characters** in the authentic CE-background result \`dat/534brn9653f9j8mmd/\`, obtains \`534965398\`, and pairs them with the nine A–I picture classes. A further speculative codebook rule demands that *matching source digits have matching Q4-selected three-mark class readouts*. A prior exhaustive D4 audit found one six-U5-master branch under a vertical flip; its combinatorial reference probability under randomized repeated-pair placement is **not a p-value for the overall hypothesis**.

Two weaknesses need their **own source control**:

1. Do Playdead-authored ARG URLs/fields generally contain enough embedded decimal characters that "the token contains nine digits" is not exceptional?
2. Can an *unrelated* original Terminal41 token yield a similarly attractive A–I equality result when the investigator is given extra degrees of freedom to choose nine of its digits?

Neither requires a new physical sticker or an additional guessed missing mark.

## Numerical caution: two incompatible reference models

If a 17-character identifier is drawn **i.i.d. uniformly from 26 letters and 10 digits**, the probability it contains exactly nine decimal digits is **1.77186%**. But that generator is *not independently identified for Playdead*; the two historical controls are around 57–59% numeric, not 27.78%.

Using the pooled comparison-token decimal fraction \`(12+13)/(21+22)=25/43\` as a deliberately illustrative Bernoulli rate yields **17.39648%** for exactly nine digits in 17 positions. The source sample size is two, the generating processes may differ, and the rate is selected with knowledge of the token family. **Neither probability is a calibrated evidential claim.** The exercise proves that the impressive-looking "nine digits in a 17-character path" rarity is completely dependent on an unverified alphabet prior.

The CE digits \`534965398\` also feature exactly **three twice-occurring digits and three singleton digits** (\`111222\` when digit multiplicities are sorted). An i.i.d. uniform nine-decimal-digit model produces this particular *unlabeled multiplicity shape* with probability

\`C(10,3) × C(7,3) × 9!/(2!³) / 10⁹ = 19.0512%\`.

Again, this is a transparent *reference calculation*, not an authorial prior. The three duplicated source digits do conveniently create equality constraints, but their count is not exotic on a uniform numeric token.

## Adversarial source controls: what if nine digits can be *chosen* from longer tokens?

For each source token, take **all** order-preserving combinations of nine of its decimal digits. Retain only nine-digit subsequences with the same \`111222\` duplicate-multiplicity pattern as the CE token. For each retained candidate, apply the *identical* equal-digit→equal-Q4-three-mark codebook operation across all eight physical D4 views and **all ten U5 physical complete masters**.

| Token | All nine-digit subsequences | Same multiplicity shape as CE | Admit any U5 master under some D4 view | Admit ≥6 masters |
| --- | ---: | ---: | ---: | ---: |
| **CE background** (9 digits) | **1** | 1 | **1** | **1** |
| **Shutdown protocol** (12 digits) | 220 | 64 | **2** | **1** |
| **SAF field** (13 digits) | 715 | 186 | **6** | **3** |

Two sample *unrelated* source-digit subsequences retaining six U5 masters are:

- From the shutdown-protocol digits: \`672390903\` (a subset of the original 12 digits);
- From the SAF field: \`346754965\` (a subset of the original 13 digits).

The finite outputs are **not independent Bernoulli trials**: the subsequences overlap heavily. The control intentionally grants *more freedom* than the CE path (where selecting all nine digits is natural), so the CE candidate is not falsified by an unrelated-token hit. **What fails is the overly confident inference that a six-state D4 codebook match is inherently too distinctive to occur in unrelated ARG material.** With additional selection freedom it visibly can occur.

The current U5 two-readout family and proposed equality rule are both products of this project's prior conjecture space. Nothing here proves a genuine original Playdead receiver or a common digit-generating protocol.

## The original game's "column first" precedent does not supply a winning sheet orientation

Keep **coordinate-pair parsing** and **image traversal** separate. The original 2016 Polybius words decode each numeric pair as **column followed by row** in a 5×5 square. They do **not** tell a solver to flatten the CE 3×3 picture column-major, and they certainly do not specify a vertical flip.

As a literal control, the speculative CE URL-digit→same-three-mark equality rule gives:

| Read order for nine CE classes | Exact U5 masters satisfying it |
| --- | ---: |
| Original 3×3 picture in its visible `IAB/CDE/FGH` rows | **0** |
| Original 3×3 picture read down each column `ICF/ADG/BEH` | **0** |
| A–I serial/cycle order `ABCDEFGHI` | **0** |
| **Top/bottom-flipped sheet `FGH/CDE/IAB`** | **6** |

The only surviving version of this *particular invented codebook* therefore needs a **specific extra physical transformation** not presently licensed by either the 2016 Polybius result or the CE background's own source identity. This is a concrete **instruction burden**, not a general impossibility for URL-derived readers. The new source-control script freezes these exact branch counts.

## Historical positive control: the original game really used a coordinate cipher

The 2016 \`LetterCode_001/002/003\` window strings are already captured in [\`scripts/audit_original_game_polybius.py\`](../scripts/audit_original_game_polybius.py). They decode with **5×5 Polybius, column before row** to \`PITYTHIS / BUSYMONSTER / MANUNKIND\`; the ordinary row-before-column alternative fails. Contemporary [Steam source discussion](https://steamcommunity.com/app/304430/discussions/0/365172547948628597/) and [Chinese contemporary summary](https://www.gamersky.com/handbook/201607/779252.shtml) independently preserve the raw-number transcription and the discovered E. E. Cummings poem target (the Chinese summary adapts English-language research, not independent algorithm discovery).

This is a genuine Playdead *method-level* prior: coordinate values → external authored text. But **its numeric domain is 1..5 per coordinate and the axis order is explicitly recovered from those 2016 bytes**. It neither determines how to map the 2019 CE's binary-zoned foreground into 5×5 coordinates nor licenses the arbitrary 9-digit URL-triplet equality operation.

The matrix witness is a better reason to keep pursuing **source-defined coordinate and lookup readers** than any apparent rarity of the CE URL's numerical count.

## Promotion gate and next work

The existing [Experiment 398](experiment-398-534brn-digit-index-replay.md) already tested a distinct, historically suggested **nine URL digits directly as one-based positions in nine 12-cell A–I class words** and obtained an ensemble-stable nine-symbol output under U3. That is **not** the same as the three-character equal-digit conjecture tested here; do not collapse those methods or count them as independent corroboration.

1. Acquire an authentic image/page/cover cue specifying **URL characters as indexes or duplicated digit labels**, including traversal and required orientation. Merely finding nine digits, D4 compatibility, or a plausible selected string is insufficient.
2. Prefer the original, demonstrated **coordinate reader** family: search source game assets and the CE cover for printed row/column delimiters, axis arrows or 3×3/5×5 table labels. Test exact source geometry before choosing a readout.
3. If testing speculative codebooks against other original material, freeze a **negative/control corpus in advance**, including source provenance and all candidate alternative tokens. State explicitly when artificial segmentation freedom is added to control tokens.
4. Keep the **closed-corpus** posture. Nothing in the present exact control implies more stickers are needed. What is missing is the source-authored **operator / receiver**.
